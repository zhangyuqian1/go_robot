# Issue 07：登录后子系统行为拆分

## 背景

登录进入场景后，可以按 `current-project.md` 描述逐步接入移动、战斗、宠物、装备、竞技场等行为。协议源来自 `gameproto/`。

## 总体要求

- 每个子系统独立开发、独立限流、独立测试。
- `gamecase` 只编排流程，不解析协议。
- `module` 负责请求、响应、推送处理和状态缓存。
- 明确哪些服务端推送可忽略，哪些必须缓存。

## 子 Issue 7.1：移动

### 协议源

- `gameproto/1.movement.proto`

### 行为

- 每帧随机方向，角度 `0~359`。
- 按固定像素步长移动。
- 移动受阻时重新随机方向。
- 收到实体移动同步后更新坐标。

## 子 Issue 7.2：战斗

### 协议源

- `gameproto/5.skill.proto`
- `gameproto/16.observer.proto`
- `gameproto/2.property.proto`

### 行为

- 检测附近怪物。
- 选择一个怪物作为目标。
- 对目标使用普通攻击。
- 目标死亡或消失后切换目标。
- 自身死亡后等待复活，复活后继续。

## 子 Issue 7.3：宠物

### 协议源

- `gameproto/19.pet.proto`

### 行为

- 收到宠物信息后立即出战。
- 宠物移除或死亡后进入冷却。
- 冷却结束后重新出战。

## 子 Issue 7.4：装备

### 协议源

- `gameproto/9.equip.proto`
- `gameproto/10.bag.proto`

### 行为

- 收到装备更新通知后处理装备。
- 单件装备随机穿戴或出售。
- 多件装备全部出售。

## 子 Issue 7.5：竞技场

### 协议源

- `gameproto/101.arena.proto`
- `gameproto/7.chat.proto`
- `gameproto/19.pet.proto`

### 行为

- 初始化时打开竞技场面板。
- 发送 GM 指令开启功能。
- 周期性请求挑战列表。
- 收到列表后延迟数秒发起挑战。
- 收到战斗结果后重置状态，冷却后进入下一轮。
- 战斗结束后重新召唤宠物。

## 验收标准

- 每个子系统至少有一个独立案例或可插入混合场景的 task。
- 每个子系统都有独立限流配置。
- 每个子系统不会阻塞 WebSocket 收包循环。
- 每个子系统失败后能恢复或明确退出。

## 当前实现入口

已注册独立案例：

- `Move`：登录进场后按 `--move-rate` 限流发送移动。
- `Battle`：按 `--battle-rate` 限流选择附近怪物并普攻，死亡后请求复活。
- `Pet`：按 `--pet-rate` 限流处理宠物出战和移除冷却。
- `Equip`：按 `--equip-rate` 限流处理装备穿戴或回收。
- `Arena`：按 `--arena-rate` 限流打开面板、请求列表、延迟挑战和结算冷却。
- `PostLoginMixed` / `混合场景`：登录后混合编排移动、战斗、宠物、装备和竞技场。

主要自定义参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--move-rate` | `5` | 移动动作限流阈值 |
| `--move-step` | `12` | 单次移动像素步长 |
| `--battle-rate` | `2` | 战斗动作限流阈值 |
| `--battle-skill-id` | `0` | 普攻技能 ID |
| `--pet-rate` | `1` | 宠物动作限流阈值 |
| `--pet-index` | `1` | 宠物出战/召唤位置 |
| `--pet-cooldown` | `10` | 宠物移除后的重试冷却秒数 |
| `--equip-rate` | `1` | 装备处理限流阈值 |
| `--arena-rate` | `1` | 竞技场动作限流阈值 |
| `--arena-list-interval` | `10` | 竞技场循环间隔秒数 |
| `--arena-fight-delay` | `3` | 收到挑战列表后的挑战延迟秒数 |
| `--arena-cooldown` | `10` | 竞技场结算后的冷却秒数 |
| `--arena-gm` | 空 | 竞技场初始化时发送的 GM 指令 |
| `--arena-index` | `1` | 挑战列表中的挑战下标 |
