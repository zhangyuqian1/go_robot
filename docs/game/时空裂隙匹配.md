# 压测案例

案例名：`TeamDungeon`，入口：`gamecase/team_dungeon.go`，已在 `CaseDefine.go` 注册。运行配置中的案例名设置为 `TeamDungeon`，其余 Gateway、账号和 `--login-rate` 配置沿用 PVP。

执行顺序：

1. 本服登录完成并收到 `s_actor_enter_scene_13` 后，发送 `c_team_dungeon_match_16(lv=1)`；匹配请求不建立响应等待标记，不重复发送。
2. 最长等待 30 秒接收 `s_team_dungeon_match_success_14`，通过单机器人容量为 1 的通道缓存匹配 ID；收到重复推送时不阻塞收包。
3. 使用推送返回的真实 `id` 发送 `c_team_dungeon_replay_19(id, replay=1)`，不使用抓包示例里的固定 ID。`s_team_dungeon_replay_15`、`s_team_dungeon_match_list_data_22`、`s_team_dungeon_match_13` 不驱动案例，无须等待。
4. 最长等待 30 秒接收 `s_start_transmit_5`，该推送结束确认请求的指标生命周期。收到有效路由后发送一次 `c_client_kick_self_5`，关闭旧连接并等待旧协程退出。
5. 保留原账号、角色 ID，重置登录状态和连接信号，按 `--login-rate` 连接路由给出的跨服 Gateway。认证参数与当前 `gamecase/start.go`、`gamecase/pvp.go` 一致，使用 `125`，不在跨服创建角色；部署参数变化时同步调整调用处。
6. 重新发送密码校验、准备登录、角色登录，校验账号未变化，使用原角色进入跨服；收到进场推送后进入登录集合点并保持在线，直到上下文取消。登录、匹配、切服等待均有超时，匹配和切服等待支持上下文取消。

本案例覆盖文档所列的“匹配 → 确认 → 跨服副本入场”，不额外发送 GM、普通地图 Boss 攻击或循环重匹配；文档尚未提供副本内目标选择、结算和退出协议。需准备满足副本等级、次数等条件的角色及足够的匹配玩家。路由中的 `addr/port` 必须是可直接连接的 WebSocket Gateway。

协议源补充说明：现有 `20.team.proto` 缺少确认请求和匹配成功推送，当前仅补流程所需最小字段并通过 `protoc` 生成 Go 代码，未声明队员列表等未使用字段。抓包 JSON 不包含 Protobuf 字段号，目前假定确认请求 `id=1`、`replay=2`，成功推送 `id=1`；上线压测前必须用服务端完整 `.proto` 核对这些字段号。单元测试只验证当前定义的编解码与路由，不能替代真实服线序校验。
